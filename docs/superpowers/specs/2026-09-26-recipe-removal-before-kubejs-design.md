# 配方移除：仅筛选原始数据包配方

## 规则

新建规则只提供两种范围：

- `OUTPUT`：按最终产物物品 ID 移除。该物品的所有原始配方都会匹配。
- `RECIPE_ID`：按唯一配方 ID 移除，只影响这一条原始配方。

已有配置中的模组、标签和配方类型规则仍可读取和撤销，界面不再创建这几类新规则。浏览配方时可以按配方类型筛选；筛选条件只改变列表，不会创建移除规则。物品搜索继续支持名称、模组 ID 和标签。

## 执行顺序

ContentStudio 在 `RecipeManager.apply` 处理原始数据包配方 JSON 时应用移除规则。判断依据是处理阶段，不检查 KubeJS 或 CraftTweaker 的命名空间、API 或运行状态。被规则命中的原始 JSON 会在 Minecraft 和脚本配方处理前移出本次输入；KubeJS 在该阶段之后写入的配方，以及 CraftTweaker 后续脚本监听器写入的配方，不会被这些规则再次检查。

配方编辑器创建的 ContentStudio 配方在较后的资源重载监听器中加入，也不受移除规则影响。若编辑器配方覆盖了其他来源的同 ID 配方，编辑器配方仍会成为最终配方。

## 目录与预览

服务端目录只记录原始数据包配方及其规则命中结果。条件不满足的配方不会作为候选项；无法解析的配方可由精确配方 ID 规则匹配，无法确认产物时不匹配 `OUTPUT`。目录中的配方预览展示原始配方状态；后续脚本写入的配方只作为当前获取方式展示，不提供移除操作。

Recipe Viewer 中的战利品、掉落、交易和信息分类属于获取来源，不作为可移除配方显示。

## 规则清理

资源重载时，如果 `OUTPUT` 规则对应的物品 ID 已不在物品注册表中，则删除该规则并保存配置。单条配方 ID 规则不会因为当前数据包暂时没有该 ID 而自动清理，以便资源包后续重新提供同 ID 配方时规则仍生效。
